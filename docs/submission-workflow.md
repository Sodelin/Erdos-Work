# Proof and submission workflow

The owner authorizes preparing, checking, publishing, and submitting qualifying mathematical results. GitHub sign-in authorization is limited to websites needed for this project. Further confirmation is not required for actions already within that authorization; a genuine account or service restriction must be reported accurately.

For each research candidate:

1. Write the exact quantified question, historical source and current finite or asymptotic scope. Search the current primary literature, problem discussions, OEIS, relevant repositories, VibeMathed and indexed X posts. Record inaccessible sources and earlier results. A table gap does not establish priority.
2. Attempt the mathematics. Record counterexamples and failed searches as such. If a known theorem is reproduced or a conjecture remains unresolved, do not advertise a new solution.
3. Verify the full intended statement. Compile Lean when a Lean proof is claimed, inspect the exported declaration and its axioms, connect custom definitions to the mathematical statement, and independently check any finite witness. Keep external baselines explicit.
4. Publish a reproducible artifact with source commit, toolchain, proof, readable argument, evidence record and real validation outcome. Keep material trust dependencies visible.
5. Submit through appropriate venues. For this project, finite A390395 extensions fit an OEIS edit and review by the register that posed the finite gap; VibeMathed decides whether a result qualifies for its catalog. Use an addendum for adjacent consequences instead of duplicate discovery claims. Prize claims require a verified applicable reward and the actual award conditions.
6. Save the receipt and notify the owner: **what was proved; where and when it was submitted; why it qualifies; how it was checked; what remains unresolved.** Publish only actual statuses: drafted, verified, public, submitted, accepted, priority-confirmed, paid.

Process check (11): inspect search coverage, source fidelity, proof compilation, statement correspondence, and reproducibility. Mathematical proof work does not receive a fabricated clinical GRADE or AMSTAR score.

Inference check (12): distinguish theorem validity from novelty, full proof from finite computation, AI review from expert endorsement, and a conditional numeric extension from an independently verified baseline. Record what would invalidate or weaken each claim.

See [current artifacts](../README.md) and the [detailed publication record](https://github.com/Sodelin/oldest-conjecture-/blob/main/docs/submission-status.md). Scheduled status checks report recorded progress; they do not constitute a continuously running proof-search service.
